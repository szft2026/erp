# H5ERP 运维手册

> 适用于 `pc/` 端（PHP 8.2 + MySQL 8）。数据库连接参数见部署时配置的 5 个环境变量。

## 一、备份

```bash
mysqldump --no-tablespaces --single-transaction --default-character-set=utf8mb4 \
  -h <DB_HOST> -P <DB_PORT> -u <DB_USER> -p'<DB_PASSWORD>' <DB_NAME> \
  > backup-$(date +%Y%m%d-%H%M).sql
```

实测：25 张表、约 170 KB、21 条 INSERT，`exit=0`。

- 备份文件包含 `ci_admin` 口令哈希，**不要提交到 Git，也不要放公开目录**。
- 建议每天一次 + 每次批量操作前一次。

## 二、恢复

```bash
mysql -h <DB_HOST> -P <DB_PORT> -u <DB_USER> -p'<DB_PASSWORD>' <DB_NAME> < backup-YYYYmmdd-HHMM.sql
```

注意：

- 恢复会 **DROP + 重建** 全部表，先确认备份文件是目标时间点。
- 恢复后管理员口令回到备份时的状态。
- 应用侧无需重启，但已登录会话（`ci_session`）会失效。

## 三、清理测试数据的原则

1. **只按明确 id 删**，例如 `DELETE FROM ci_goods WHERE id IN (13,14);`
2. **禁止** `DELETE ... WHERE name LIKE 'ZZ%'` 这类批量删——曾经因此把唯一的结算账户一起删掉。
3. 删之前先按第一节做一次备份。
4. 删除基础资料前先查引用：

```sql
SELECT COUNT(*) FROM ci_invoice_info WHERE invId = ? AND isDelete = 0;   -- 商品是否被单据引用
SELECT COUNT(*) FROM ci_invoice      WHERE buId  = ? AND isDelete = 0;   -- 往来单位是否被引用
SELECT COUNT(*) FROM ci_account_info WHERE accId = ? AND isDelete = 0;   -- 账户是否有流水
```

## 四、常见故障

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 付款单/收款单「结算账户」下拉为空 | `ci_account` 无数据 | 在「设置 → 结算账户」新增；或直接补：`INSERT INTO ci_account (id,name,number,status,amount,date,type,isDelete) VALUES (5,'现金','1001',1,0,CURDATE(),1,0);`（type：1 现金 / 2 银行存款） |
| 客户下拉里出现供应商 | `type` 参数放在了 POST body | `type` 必须放 URL query（源码用 `input->get`），`type=10` 客户、`type=-10` 供应商 |
| 类别下拉为空 | `typeNumber` 同样只认 query | `basedata/assist?action=list&typeNumber=trade`（客户类别 `customertype`、供应商类别 `supplytype`、结算方式 `PayMethod`） |
| 单据保存报「提交的是空数据」 | 单据类接口要整单 `postData`（JSON 字符串） | 见接口文档 2.3–2.11 |
| 打印返回 0 字节 | 老版本只认 POST | 现版本 GET/POST 均可：`GET /scm/invSa/toPdf?id=124` |
| 导入报「模板不匹配」 | 表头不是 `商品编号`/`客户编号`/`供应商编号` | 重新下载对应模板，不要改表头 |
| 导入「无可导入的数据」 | 模板只有表头没有数据行 | 填数据后再传 |
| 删除单据报「已审核的不可删除」 | 业务规则 | 先反审核再删除 |

## 五、部署与升级

- **blitz.cloud**：仓库根 `Dockerfile`，平台选 `app`，构建后自动上线；环境变量只需 `DB_HOST/DB_PORT/DB_DATABASE/DB_USERNAME/DB_PASSWORD`。
- **自有 Docker**：`docker compose up -d --build`（内置 MySQL 8）或 `docker-compose.external.yml`（接外部库）。
- **直接装 Apache/Nginx**：见 `DEPLOY-php-server.md`。

升级步骤：备份 → 拉新代码 → 重建镜像/重启 → 回归（登录、开单、打印、报表）。

## 六、日志与排查

| 位置 | 内容 |
| --- | --- |
| `pc/data/backup/*.sql` | 系统内「备份与恢复」生成的整库导出 |
| `pc/data/upfile/import/*.xls(.json)` | Excel 导入留痕：原文件 + 结果 |
| `ci_log` | 业务操作日志（新增/审核/删除/登录） |
| 容器日志 | PHP / Apache 错误，`docker logs <容器>` |

排查顺序：先看接口返回的 `status/msg`，再查 `ci_log`，最后查 PHP 错误日志。
